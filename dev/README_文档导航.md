## 协作纪律（站长定，2026-10-04；违反即为沟通事故）


### 一、不许制造验证

没有自己解码出来的客户端包（或等价的一手证据），就不写"已修复 / 已验证"，只写"改了 X，尚未验证"。

不把结论塞进问题里做引导性提问。要问就要求对方描述可观测的具体项，并允许对方回答"没看 / 不知道"。

对方的回话如果不是自发、具体的观察（只是重复我的措辞、顺口答应），一律记为"未验证"，

不写进任何文档的验收段。

### 二、一次只动一个变量

一个假设等于一次改动加一次测量。测量优先用我自己能读的数据（抓包、日志、库表），

需要站长游戏内观察时，一次把要看的项全部问完，不来回要人看。

上一个改动没被证实就先回滚，再谈下一个，不叠加未验证的行为改动。

### 三、两次不收敛就停

同一个问题，连续两次"改了但没解决"之后必须停下来，给出选项（继续查 / 回滚 / 搁置）并说明各自代价，

不再自行试第三次。

### 四、不误导性汇报

汇报里区分"我做了什么"和"事实是什么"；结论句必须能指到证据（日志行、包字节、库表值）。

对方的批评如果指向前几轮的错误，先承认再往下走，不解释成"运气不好"。

### 五、给站长的成本意识

编译加重启一次的代价包含站长必须重新登录、重新跑测试。能靠离线数据（抓包、离线地图探针、库查询）判断的，

不要用"改代码看效果"来试。
